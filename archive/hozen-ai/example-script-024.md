# 故障報告書をAIで5分で書く（台本例）
※「5分」「3分」は演出上の仮置き。必ず実測して差し替える

**タイトル案**
- 故障報告書をAIで5分で書く方法｜保全マンの時短術
- 【保全】故障報告書が5分で終わる、AIへの頼み方
- 故障報告書、AIに丸投げすると危ない理由と正しい使い方

**サムネイル**：左に殴り書きメモ、右に整った報告書、中央に「5分」

[0:00] 画面：現場メモと完成報告書を並べる
「故障報告書、これ5分で書けます。しかも上司に突き返されない形で。」

[0:05] 「復旧でヘトヘトになった後に報告書。何を書けばいいか分からず、気づけば1時間……保全あるあるですよね。」

[0:20] 「今日はAIを"聞き取り役"にして、メモから報告書を作る手順を実際の画面で見せます。途中で、AIが書いた報告書をそのまま出すと危ない理由もお見せします。使ったプロンプトは概要欄に置いておきます。」

[0:35] 第1章：なぜ報告書は時間がかかるのか
「原因は3つ。書く順番が決まっていない。原因と処置が混ざる。再発防止があいまいになる。"現象・影響・原因・処置・再発防止"の5つで書けば、まず外しません。」

[1:30] 第2章：実演
画面：メモ「3号コンベア停止、サーマル動作、リセットで復旧、ベアリング付近で異音」
「いきなり"報告書を書いて"と頼まないのがコツです。『あなたは保全課長です。このメモで報告書を書く前に、足りない情報を5つ質問してください』」
画面：AIの質問（停止時間、電流値、前回点検日など）
「答えると、5項目に沿った報告書が出てきました。ここまで約[要実測]分です。」

[3:30] 第3章：落とし穴
「ここを見てください。『原因：ベアリング劣化』と断定しています。でも実際はまだ分解確認していません。そこで1行足します。『確認済みの事実と推定を分けて書いて』。原因欄が"推定"と明記されました。今日いちばん伝えたいのはここです。」

[5:00] 第4章：機密の扱い
「社名や設備番号は記号に置き換えてから入力してください。AIの使い方は先に社内ルールを確認しましょう。」

[6:00] まとめ＋CTA
「ポイントは3つ。5項目で書く。先にAIに質問させる。事実と推定を分ける。プロンプトは概要欄に。原因をもっと深掘りしたい人は、次の"なぜなぜ分析をAIと一緒にやる"をどうぞ。」
